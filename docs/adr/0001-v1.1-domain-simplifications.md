# v1.1 领域模型相对 PRD v1.0 的简化

为适配"纯本地、双击 `file://` 即用、离线零依赖"的 Demo 约束，v1.1 将 PRD v1.0 中三个模块的领域模型做了有意的简化，导致代码与 PRD 分叉。本文记录该决策，避免后人"修复"本属故意的设计。

**Status**: accepted

## 三处分叉
1. **工作计划**：PRD 的"项目 → 任务"两级（含优先级/状态/截止日）扁平化为"计划卡 → 工作内容"（仅 `text`/`done`）。`work.js` 顶部注明"卡片式，PRD §5.2 简化模型"；`store.js` 的 `normalize()` 在导入旧数据时丢弃 `projectId`/`title`/`dueDate`/`priority`/`status`。
2. **健身计划**：PRD 的"训练模板 + 打卡(组次重)"改为"训练日程：日期 → 训练部位(胸/肩/背/腿/有氧) + 5 个固定动作(done)"月历模型；`templates`/`checkins` 字段保留为遗留、不再写入。
3. **饮食计划**：PRD 食物项用整份绝对值，v1.1 改为食材"每 100g"基准 + 记录条目带克数(`grams`)与折算营养；新增"饮水 `waterMl`"；`targetKcal` 未实现。

## 动机（真实取舍）
- 本地离线单人 Demo：不需要优先级/状态流转/组次重等协作与进阶追踪能力，扁平模型更易演示、更易维护。
- `file://` 约束：无构建、无框架、无后端，降低复杂度优先。
- 饮食改"每 100g"基准：让"同一食材不同份量"可复用营养数据，比整份绝对值更实用。

## 后果（Consequences）
- PRD v1.0 已过期；后续需求应基于 v1.1 代码而非 PRD 原文。
- 若未来回归 PRD 丰富模型（优先级/状态、训练模板/组次重、每日目标热量），需数据迁移并改写对应视图，成本中等。
- 命名已切换：项目/任务 → 计划卡/工作内容；训练模板/打卡 → 训练部位/动作。新代码与文档一律用新术语，避免混用旧词。
