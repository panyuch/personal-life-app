# Spec: 首页总览布局对齐风格原型（home-restructure）

**Status:** ready-for-agent

> 来源：一次性 UI 风格原型（`prototype-ui-styles.html`，含 5 套风格 + 首页骨架 + 底部切换条）→ grilling 设计树收敛（2 轮）+ to-spec 测试缝对齐。
> 目标：把「首页总览」的布局结构重构为与原型一致（区块顺序、层级关系、响应式行为对齐），同时适配 v1.1 技术栈与样式规范。

## Problem Statement

使用者（个人生活 App 的单一使用者）已通过一次性风格原型确认了满意的首页视觉结构：左侧带图标导航、右侧顶栏 + 问候条 + 卡片网格 + 「核心模块预览」区块。但原型是 throwaway 代码，其布局结构与正式 App 的首页总览不一致——正式版缺侧边栏图标、问候条被包成卡片、缺少「核心模块预览」区块、摘要卡用纯文本而非数字条/进度条。需要把正式首页的 DOM 结构与视觉呈现对齐到原型，同时沿用 v1.1 的真实数据模型与 `data-skin` 换肤机制。

## Solution

重构「首页总览」的渲染与骨架：侧边栏导航补图标；问候条改为独立区块并带动态待办统计；第一块卡片网格保留 5 张摘要卡但内部改为数字条/进度条呈现；新增「核心模块预览」第二区块（健身月历 / 饮食三餐 / 身体数据趋势三张只读预览卡，可点击跳转）。所有预览卡读 v1.1 真实数据、与各业务模块同源。布局与响应式对齐原型（`@media 720px` 侧栏转顶部横排）。

## User Stories

1. 作为使用者，我打开首页总览能看到带图标的左侧导航，以便快速辨识六个入口。
2. 作为使用者，我打开首页能看到顶部问候条（时段问候 + 昵称）而非被卡片包裹的问候，以便首页更聚焦。
3. 作为使用者，问候条副文案能显示「今天有 N 件待办，保持节奏。」这类动态统计，以便一眼知道当天待办量。
4. 作为使用者，首页第一块卡片网格仍依次展示今日计划 / 快速备忘 / 工作计划 / 健身计划 / 饮食计划，以便与之前一致。
5. 作为使用者，工作计划摘要卡以数字条（计划数 / 内容数 / 已完成数）呈现，以便快速掌握工作概况。
6. 作为使用者，健身计划摘要卡显示今天有无训练与最近体重，以便快速了解健身状态。
7. 作为使用者，饮食计划摘要卡显示今日是否已记录与今日热量，以便快速了解饮食状态。
8. 作为使用者，我能在首页勾选今日计划项、随手记备忘，勾选后与今日计划模块同步，以便首页仍支持轻操作。
9. 作为使用者，首页新增「核心模块预览」区块，包含健身月历 / 饮食三餐 / 身体数据趋势三张卡，以便不进入模块也能看到细节。
10. 作为使用者，健身月历预览卡只读展示当月训练部位与完成 ✓ 标记，点击整卡进入健身计划，以便快速跳转。
11. 作为使用者，饮食三餐预览卡展示当日四餐（早餐 / 午餐 / 晚餐 / 加餐）真实条目，点击进入饮食计划，以便快速查看与跳转。
12. 作为使用者，身体数据趋势预览卡展示体重折线与蛋白 / 碳水 / 脂肪宏量条，点击进入健身计划，以便快速查看与跳转。
13. 作为使用者，预览卡的数据与各模块真实数据一致（同源），以便首页信息可信。
14. 作为使用者，各预览卡在无数据时显示空态引导（如「暂无身体数据」），以便理解为何空白。
15. 作为使用者，首页在五套界面风格（野兽派 / 编辑杂志 / 新拟物 / 现代渐变 / 赛博朋克）下都能正确呈现新结构，以便换肤不破坏首页。
16. 作为使用者，编辑杂志风格下首页卡片标题仍显示编号（01–05 / A–C），以便保持该风格的编号观感。
17. 作为使用者，在窄屏（≤720px）下首页布局转为顶部导航 + 单列内容，与原型响应式行为一致，以便小窗可用。

## Implementation Decisions

### 骨架与导航

- 侧边栏每个导航项新增图标元素（◉ 首页总览 / ☐ 今日计划 / ▤ 工作计划 / ◍ 健身计划 / ◔ 饮食计划 / ◈ 数据与设置），图标 + 文字同行排列；这是全站共享骨架改动，影响所有页面。
- 首页顶栏主按钮保持隐藏（首页以看 + 轻操作为主，无统一「新建」语义）。

### 问候条

- 问候条从卡片改为独立区块（非 `.card`）：标题行「时段问候 + 昵称」，副文案为动态待办统计「今天有 N 件待办，保持节奏。」；N 取今日未完成待办数，N 为 0 时改用鼓励文案。
- 时段问候复用既有 `Home.greeting`（早 / 下午 / 晚）。

### 第一块卡片网格（5 卡，编号 01–05）

- 今日计划卡：今日未完成前几条 + 复选框（勾选同步今日计划模块）+「查看全部 →」。
- 快速备忘卡：输入框随手记 + 备忘列表（勾掉 / 删除）。
- 工作计划摘要卡：数字条呈现「计划数 / 内容数 / 已完成数」，整卡点击进入工作计划。
- 健身计划摘要卡：今天有无训练（部位）+ 最近体重（含日期），整卡点击进入健身计划。
- 饮食计划摘要卡：今日是否已记录 + 今日热量，整卡点击进入饮食计划。
- 卡片标题加 `data-no` 编号（01–05），供编辑杂志风格的编号观感命中（既有皮肤已按 `attr(data-no)` 渲染编号）。

### 核心模块预览（第二区块，编号 A–C，可点击跳转）

- 区块标题「核心模块预览」使用分节标题样式（居中文本 + 分隔线）。
- 健身月历卡：只读迷你月历，读当月「训练日程」，每格显示日期 + 训练部位（含部位色）+ 已完成 ✓ 标记；月历内不翻月、不选中、不设置部位；整卡点击进入健身计划。
- 饮食三餐卡：读当日四餐（早餐 / 午餐 / 晚餐 / 加餐）真实「饮食记录条目」，显示条目名称与份量/热量；整卡点击进入饮食计划。
- 身体数据趋势卡：读「身体数据」按日期排序绘制体重折线（委托图表适配器）+ 蛋白 / 碳水 / 脂肪三条宏量条；无身体数据时显示空态；整卡点击进入健身计划。

### 数据同源与 v1.1 适配

- 所有预览卡读 v1.1 真实数据，与各业务模块同源（工作计划摘要 / 健身摘要 / 饮食摘要分别复用既有 `summary` / `dailySummary` 等聚合接口）。
- 不引入 v1.0 的「每日目标热量」「到期 / 逾期 / 进行中」概念；饮食卡不展示目标进度条，仅展示今日热量。
- 训练部位色沿用既有「按风格主题化的部位色」机制。

### 样式组织

- 新增组件的基础布局样式（图标、问候条、分节标题、数字条、进度条、迷你月历、三餐、宏量条）统一放入通用样式层，颜色/形状走 CSS 变量。
- 各界面风格对新增组件的差异化（野兽派粗边、编辑杂志编号、新拟物浮雕、现代渐变渐变、赛博朋克霓虹）统一放入皮肤样式层，按真实组件类名覆盖。
- 响应式沿用 `@media 720px` 断点：侧栏转顶部横向导航、内容单列，与原型一致。

### 图表

- 身体数据趋势折线委托既有图表适配器（`W.Chart.renderWeightTrend`），不在首页重写绘图逻辑；无数据时不绘图、显示空态。

## Testing Decisions

- 好测试标准：只测外部可见行为（渲染输出的结构、与各模块数字的同源一致性），不测内部实现细节与具体 CSS 值。
- 主缝：`Home.build(ctx)`（既有，返回 HTML 字符串）——断言新增结构子串（问候条、分节标题、数字条、迷你月历、三餐、宏量条、编号）与各模块聚合数字一致。
- 图表缝：`W.Chart.renderWeightTrend`（既有适配器缝，注入假 Chart）——断言「身体数据趋势」卡把 body 体重数据正确委托给图表适配器（`{dates, weights}`）。
- 不新增模块边界缝：迷你月历 / 三餐 / 宏量条作为 `build()` 内部纯字符串函数，通过 `build()` 输出断言。
- 先例：`phase6.test.js` 的 `H.includes(html, …)` 结构断言与 `build`/`render` 冒烟；`chart-adapter` 的假 Chart 注入。
- 回归：更新 `phase6.test.js` 中受结构变化影响的旧断言（问候从卡片改独立区块、工作计划摘要从纯文本改数字条），新增「核心模块预览」渲染用例，跑全量测试确认无回归。

## Out of Scope

- 不重开 ADR-0001（v1.1 领域简化）与 ADR-0002（图表适配器缝）。
- 不引入 v1.0 的「每日目标热量」与「到期 / 逾期 / 进行中」概念。
- 不迁移原型的底部悬浮切换条；界面风格仍走 `data-skin` + 数据与设置页切换。
- 首页预览卡只读（月历不翻月 / 不选中 / 不设置部位），仅支持整卡点击跳转。
- 不改动各业务模块自身的视图与数据模型。

## Further Notes

- 术语沿用 CONTEXT.md：首页总览 / 今日计划 / 工作计划 / 健身计划 / 饮食计划 / 训练日程 / 训练部位 / 身体数据 / 餐次 / 饮食记录条目 / 当日汇总 / 备忘 / 界面风格。
- 「核心模块预览」三张卡可点击跳转为使用者在设计树访谈中的明确选择（与实现者的「纯展示」推荐相反，按使用者意愿执行）。
- 饮食卡不展示目标进度条，因 v1.1 无目标概念；如需后续引入目标热量，另开需求。
- 侧边栏图标为全站共享改动，实施后需在全部页面确认导航视觉无异常。
